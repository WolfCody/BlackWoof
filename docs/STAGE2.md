## 3. Зависимости и политика логирования

Прямые (2):

| Крейт | Зачем |
|---|---|
| `symphonia =0.6.0`, `default-features = false`, features `flac mp3 ogg pcm vorbis wav id3v1 id3v2` | Декодирование MP3, FLAC, WAV/PCM, OGG Vorbis. AAC и Opus не включены. Без `opt-simd*`, чтобы не тянуть `rustfft`. |
| `log 0.4` с feature `max_level_off` | **В коде не используется.** Каждый крейт Symphonia зависит от `log`, убрать его из дерева нельзя. Эта строка вырезает все вызовы `log` при компиляции, в любом профиле, включая release. Логгера нет. |

Транзитивные: служебные крейты Symphonia и мелкие общие библиотеки. Точный список даёт `cargo tree`; CI кладёт его в `build/deps.txt`.

Политика в CI (шаг «Dependency policy»):

- **Запрещены** реальные реализации логирования (`env_logger`, `android_logger`, `tracing*`, `fern`, `simplelog`, `log4rs`, `slog*`, `syslog` и т. п.) и сетевые крейты.
- **Разрешён только** фасад `log`, и только в отключённом виде. Это проверяется строго (`scripts/check_log_facade.py` по `cargo metadata`): в графе ровно одна версия `log`, и у неё включён `max_level_off`. Отсутствие feature или несколько версий — ошибка, а не предупреждение.
- `cargo tree -e features -i log` печатается для ручного просмотра (`build/log-features.txt`).
- `verify_apk.sh` падает, если библиотека ссылается на `__android_log*` или линкуется с `liblog`.
- В `src/` и `java/` нет логгеров, `println!`, `System.out`, `android.util.Log`, инициализации логгера; счётчиков и диагностических буферов нет.

## 4. Архитектурные решения

1. **Один поток воспроизведения на трек** (`bw-audio`): декодирование → блокирующая запись в AAudio. На паузе поток спит на condvar.
2. **Вывод:** AAudio, shared, `POWER_SAVING`, i16, usage MEDIA, content MUSIC. Формат потока проверяется после открытия: несовпадение частоты, каналов или формата даёт ошибку вместо неверной скорости. Размер буфера выбирает система.
3. **Порция 4096 кадров** (`CHUNK_FRAMES`); подбор — Stage 7, по измерениям.
4. **Формат известен до открытия вывода.** `Decoder::open` декодирует первый пакет, поэтому битый файл не открывает AAudio.
5. **Обложки не загружаются.** Для метаданных задан `limit_visual_bytes = Limit::Maximum(1)`: ридеры пропускают картинки, а не держат их в памяти весь трек. CI-фикстура `stereo_cover.mp3` с большой обложкой проверяет, что такой файл всё равно открывается и декодируется. **Поведение пропуска в Symphonia 0.6.0 до первого запуска CI не проверено.**
6. **Повреждённые данные:** плохие пакеты пропускаются (до 256 подряд), обрезанный файл — конец трека; более 2 каналов отклоняются; частота 8–192 кГц.
7. **Владение FD.** `detachFd()` → `take_fd` (проверка `fcntl(F_GETFD)`) → `File` у декодера → закрытие ровно один раз при любом исходе. Итоговое состояние публикуется после закрытия файла.
8. **Паники:** `catch_unwind` в каждой JNI-функции и в потоке воспроизведения; panic hook молчит; `panic = "unwind"`.
9. **Ошибки:** `ErrorKind` без текста и истории; состояние перезаписывается следующим `play`.
10. **Ошибки вывода:** до 3 переоткрытий на трек, затем `FAILED`.

## 5. Решения владельца (приняты)

- Имя пакета `com.dzekiwolf.blackwoof` окончательное.
- Symphonia 0.6.0 с `id3v1` и `id3v2`; `log` — только в полностью отключённом виде.
- Единственное постоянное состояние — последнее воспроизведение. Язык, цвет текста, Shuffle/Repeat и любые настройки не сохраняются.
- Красный цвет текста — функция Stage 5, действует только в текущем сеансе. Язык первой версии — русский; переключение ru/en отложено.
- Только mono и stereo; многоканальный звук пока не реализуется.
- Обложки не извлекаются, не загружаются без необходимости и не хранятся.

## 6. Ограничения Stage 2

- Нет перемотки, позиции, плейлиста и сохранения состояния (Stage 3–4).
- Нет foreground service, MediaSession и аудиофокуса: **поведение в фоне не определено**. Тестировать только с открытым приложением.
- `MainActivity` — временный стенд: чёрный фон, серый текст, текстовые кнопки, обновление только после нажатия и в `onResume`.

## 7. Cargo.lock, повторяемость, подпись

- **Cargo.lock.** Если файла нет, CI выполняет `cargo generate-lockfile`, затем экспортирует `LOCKED=--locked` для всех следующих шагов; `cargo test`, `cargo tree`, `cargo metadata`, `cargo build` и `cargo clean` идут с `--locked`. Скрипт сборки сам определяет наличие файла и использует `--locked`, если он есть. Сгенерированный, но не закоммиченный `Cargo.lock` **не закрепляет версии между отдельными запусками**: закоммитьте его из артефакта.
- **Повторяемость.** Сравниваются SHA-256 `libblackwoof.so` и `classes.dex` из двух чистых сборок одного запуска. Это проверка повторяемости этих двух файлов, а не воспроизводимости всего APK. Подписанные APK не сравниваются, поэтому разные ключи не дают ложных расхождений.
- **Подпись.** Временный ключ в `RUNNER_TEMP`, вне репозитория; пароль случайный, передаётся через окружение и не печатается; удаляется ловушкой `EXIT` при успехе и ошибке. Поддерживаются `KEYSTORE_B64`, `KEYSTORE_PASS` (теперь обязателен вместе с `KEYSTORE_B64`) и `KEY_ALIAS`. Артефакты — явный список файлов; ключей среди них нет.

## 8. Как проверить на телефоне

1. GitHub → Actions → запуск → Artifacts → `blackwoof-stage2`: `BlackWoof-stage2.apk`, `Cargo.lock` и отчёты. Закоммитьте `Cargo.lock`.
2. Установите APK. Ключ создаётся заново при каждой сборке, поэтому старую версию сначала удалите.
3. `[ OPEN ]` → файл. По одному MP3 (с тегами и обложкой), FLAC, WAV, OGG. Ожидается звук и `State: PLAYING`.
4. `[ PAUSE ]`, `[ RESUME ]`, `[ STOP ]`, результат видно по `[ STATUS ]`.
5. Конец трека → `ENDED`.
6. Битый файл (текст с именем `.mp3` или обрезанный MP3) → `FAILED` с короткой причиной, приложение живо, следующий файл играет.
7. Быстрая смена трека 10–20 раз.
8. Отключение наушников или подключение Bluetooth во время игры.
9. 10–30 минут воспроизведения с открытым приложением; щелчки и пропуски записать.
